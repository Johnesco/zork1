Zork I: Inform 7 Edition — Testing Guide

This project uses a two-layer testing system: built-in Inform 7 Test commands for interactive development and RegTest (by Andrew Plotkin) for automated regression testing.

Local only. The tests/ directory is not deployed to GitHub Pages. The built-in Test commands in story.ni are in a "Not for release" section and are stripped from release builds.

Prerequisites

  • WSL (Windows Subsystem for Linux) — required to run the CheapGlk glulxe interpreter
  • Python 3 — available on both Windows and WSL (RegTest runs via WSL Python)
  • CheapGlk glulxe binary — pre-built at /home/johnesco/glulxe/glulxe in WSL (also copied to tools/glulxe, which is gitignored)
  • Compiled game — build/zork1.ulx (the Glulx story file)

Quick Start

Run all tests

wsl -e bash -c 'cd /mnt/c/code/zork1 && bash tests/run-tests.sh'

Run a single test

wsl -e bash -c 'cd /mnt/c/code/zork1 && bash tests/run-tests.sh cellar'

Verbose mode (see full game transcript)

wsl -e bash -c 'cd /mnt/c/code/zork1 && bash tests/run-tests.sh -v'

List all available tests

wsl -e bash -c 'cd /mnt/c/code/zork1 && bash tests/run-tests.sh -l'

Verbose with stop-on-first-error

wsl -e bash -c 'cd /mnt/c/code/zork1 && bash tests/run-tests.sh -v --vital cellar'

How it works

  1. run-tests.sh invokes regtest.py with the CheapGlk glulxe interpreter and the compiled zork1.ulx
  2. For each test in zork1.regtest, RegTest spawns a fresh game instance
  3. Commands are piped to the interpreter via stdin; output is read from stdout
  4. Each assertion line is checked against the game's output for that turn
  5. Tests pass silently; failures report the assertion and line number

RegTest File Format

The .regtest file uses a simple line-based format:

# Comment
** game: ../build/zork1.ulx
** interpreter: /home/johnesco/glulxe/glulxe -q

* test-name
> command to send to game
Literal text that must appear in output
/regex pattern that must match (NO trailing slash)
!text that must NOT appear in output
{vital}                    (abort test on failure)
>{include} other-test      (include another test's commands)
Important: Regex lines start with / but do not have a trailing /. The line /West of House is correct. The line /West of House/ would try to match a literal trailing slash.

Test composition with {include}

Tests can build on each other. For example, echo includes round-room, which includes troll, which includes cellar, which includes living-room, and so on. This avoids duplicating navigation sequences.

* cellar
>{include} living-room
> push rug
/trap door
> open trap door
/rickety staircase
> down
/Cellar

* troll
>{include} cellar
> n
> attack troll
...

Built-in Test Commands (story.ni)

Part 6 of story.ni contains Inform 7 Test commands that work inside the game at the command prompt. These are available in debug builds only ("Not for release").

> test cellar
> test feedcyclops
> test odysseus
> test echo
> test dam
> test exorcism
> test diamond
> test boat
> test scarab
> test rainbow
> test mirror
> test bauble
> test dome

Unlike RegTest, these use Inform 7's built-in holding and in clauses to set up preconditions (starting location, held items), making them useful for quickly testing individual puzzles without navigating there manually.

Note: These require the game to be recompiled with the current story.ni. The pre-existing build/zork1.ulx was compiled from an older source and will report "No test scripts exist."

Known Limitations

  • Troll combat is random (~70% hit rate per swing). Tests that traverse the troll may occasionally fail. Just re-run.
  • WSL required. The CheapGlk glulxe is a Linux ELF binary. RegTest uses select.select() which is POSIX-only. All tests must run through WSL.
  • Compiled .ulx may lag behind story.ni. The build/zork1.ulx may be compiled from an older source. Features like turn bolt and rub mirror currently give default Inform responses in the compiled game. Tests accommodate this with comments noting expected behavior after recompilation.
  • Thief interference. The thief roams every 5 turns and can steal items or block movement. Long test sequences may encounter unexpected thief interactions.

Adding New Tests

  1. Open tests/zork1.regtest
  2. Add a new test block: 
    * my-new-test
# Description of what this tests
>{include} cellar
> go north
/expected output text
> do something
!text that should NOT appear
  3. Run it: wsl -e bash -c 'cd /mnt/c/code/zork1 && bash tests/run-tests.sh -v my-new-test'
  4. If it passes, run the full suite to make sure nothing else broke

Tips

  • Use {include} to build on existing navigation sequences rather than duplicating commands
  • Use {vital} before key assertions to abort early on fundamental failures
  • Prefer regex (/pattern) over literal text when the exact wording might change
  • Use ! negated checks to verify unwanted behavior doesn't appear
  • Keep tests independent — each test starts a fresh game instance

Rebuilding the CheapGlk Glulxe

If the WSL binary at /home/johnesco/glulxe/glulxe is lost, rebuild from source:

# In WSL:
cd ~
git clone https://github.com/erkyrath/cheapglk
git clone https://github.com/erkyrath/glulxe
cd glulxe
# Edit Makefile: set GLKINCLUDEDIR and GLKLIBDIR to ../cheapglk
cd ../cheapglk && make
cd ../glulxe && make
# Result: ~/glulxe/glulxe
cp ~/glulxe/glulxe /mnt/c/code/zork1/tools/glulxe
Note: If sudo is unavailable in WSL, gcc/make can be installed via apt-get download + dpkg-deb -x into a local prefix. See the project's git history for the original build process.
